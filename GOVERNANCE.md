# Governance

This file tells who maintains Healthpipe, how the maintainers make decisions and where you get support.

## Maintainers

[Enversion Journl ApS](https://docs.journl.dk/v1/) develops and maintains Healthpipe. The maintainers are the members of the GitHub team `@enversion-journl/developers`. `.github/CODEOWNERS` makes this team the owner of all files.

## Decisions

Healthpipe uses a maintainer-led model:

- The maintainers decide the scope of the project and the roadmap.
- The maintainers review and merge the pull requests. Each pull request needs a review before it merges.
- For a larger change, open an issue first. The maintainers discuss the design with you in the issue before you start the work.
- When contributors do not agree, the maintainers make the decision. They give the reason in the issue or in the pull request.

## How to become a maintainer

The maintainers invite new maintainers. They look for a contributor who:

- Makes good contributions over a long period, for example code, tests, documentation or reviews.
- Knows the project patterns and obeys [CONTRIBUTING.md](CONTRIBUTING.md).
- Helps other users in the issues.

An organization that uses Healthpipe can ask for maintainer access for one of its developers. The same rules apply.

## Releases

The maintainers make all releases. Each release replaces the tree on `main`, as [How a Release Replaces the Tree](CONTRIBUTING.md#how-a-release-replaces-the-tree) describes. [Releases](CONTRIBUTING.md#releases) gives the version rules. [CHANGELOG.md](CHANGELOG.md) lists the changes of each release.

## Support

- **Community support**: use the GitHub issue forms (**Question**, **Bug report** or **Feature request**). The maintainers answer on a best-effort basis. They do not give a response time.
- **Security**: do not open a public issue. Report a vulnerability privately, as [SECURITY.md](SECURITY.md) describes.

## Adopters

[ADOPTERS.md](ADOPTERS.md) lists the organizations that use Healthpipe. The list starts empty. To add your organization, open a pull request that adds one row to the table. [ADOPTERS.md](ADOPTERS.md) gives the steps.

## Code of conduct

All participants must obey the [Code of Conduct](CODE_OF_CONDUCT.md).

**Which obligations does the AGPL give?**
The obligations depend on how you use, change and share Healthpipe. Read the conditions in [LICENSE](LICENSE), especially section 13 about network use of a modified version.

That depends on your setup, for example who uses a modified version over a network. Ask your legal team.
